# Pibardos OP

**Intentionally hidden pending redesign:** Mi colección, Lista de deseos and Cartas que me faltan. Their code and existing data remain intact; `collectionEnabled` in `src/lib/features.ts` controls visibility. Navigation, card-detail controls and the deck’s missing-card action stay hidden. A Spanish mobile-first personal workspace for One Piece Card Game. The app includes secure authentication, provider-backed cards, OPTCG API card imports, confirmed deck imports, a deck builder with internal immutable match snapshots, match history, tournaments, physical collection, missing-card reservations, exact-art wishes and charts of saved results. Practice and offline synchronization are subsequent phases; see `PROJECT_STATUS.md` and `docs/ARCHITECTURE.md`.

## Local development

For Windows, install Node.js 24, Git and Docker Desktop with the WSL 2 / Linux-container engine. Open Docker Desktop before starting. Clone the repository into a user-owned folder and open it as a **local** project in your desktop coding app:

```powershell
git clone https://github.com/suyoyi/PibardosOP.git
cd PibardosOP
npm run local:start
```

`local:start` restores locked dependencies when the lockfile changes, starts and verifies Supabase and applies pending local migrations, creates public `.env.local` settings only when absent, builds the application and starts a foreground loopback server. After checking the actual health and login form, it opens the default browser (PowerShell `Start-Process` on Windows). Keep the terminal open. Ctrl+C stops the web server; `npm run db:stop` stops local Supabase while retaining data. Existing healthy instances and configuration are preserved. To use a different port set `PIBARDOS_APP_PORT`; to suppress browser opening set `PIBARDOS_OPEN_BROWSER=false`.

This cloud chat cannot execute commands on your Windows PC. Once the repository is open in a local desktop-agent session, ask that session to run `npm run local:start`. Browser preview inside the desktop app still depends on that app's available tools; the normal Windows browser works independently.

Requirements: Node 22.12+ (validated with Node 24), npm, Docker with a running daemon. Dependencies are pinned in `package-lock.json`.

```bash
npm ci
npm run db:start
npm run setup:local
npm run dev
```

`setup:local` creates an ignored `.env.local` using the **public** local URL/key from CLI status. It refuses to overwrite an existing file and never copies a service-role key. Local signup does not require email confirmation; local accounts are development-only. Private saved cards start empty; Roronoa Vinny, Rocks D. Bermejo and their verified canonical references are seeded as read-only shared catalog entries, while **Cartas** automatically displays the available English provider catalog. Manual creation is retired; missing source cards remain explicit unknowns. Previous manual entries remain private, readable and labeled unverified. Do not load synthetic test fixtures into production.

The Supabase wrapper keeps CLI state in a writable sibling `.supabase-cli` directory (override with `SUPABASE_HOME`) and selects the CLI's official digest-pinned reduced images via `SUPABASE_USE_SLIM_IMAGES=true`. The standard PostgreSQL image exceeded this cloud Docker daemon's storage capacity. Keep the same image-family setting when restarting or resetting the database. Optional Studio, Storage, Realtime, analytics and Edge services are disabled for this phase. The PostgreSQL/Auth/API gateway services are required. Containers/volumes retain local development data; live processes must restart after a cloud snapshot restore.

On this cloud host, the injected HTTP proxy makes the container's BusyBox `wget` loopback Auth probe return 403 while the actual gateway health endpoint returns 200. Use `PIBARDOS_HTTP_READINESS=true npm run db:start` here. This documented opt-in replaces the failing Docker probe with mandatory PostgreSQL `select 1`, Auth health JSON and PostgREST OpenAPI checks; the script still fails if any actual service is unavailable. Normal environments retain the CLI's container health checks by default. Functional authentication is additionally verified by E2E tests. This is a local proxy workaround, not a production setting.

Source `Day1`–`Day13` are drawn in field order; the last quote appears separately and in the table. The API documents neither individual dates nor chronological direction, so the graph does not invent dates, calculate trend percentages or fill missing values. Set/starter history is supported; promos/DON show the source limitation. Failed history requests leave current prices/details intact and offer explicit retry. Unknown prices are absent, zero remains zero, and the API's undeclared currency is stated explicitly. No import or physical ownership is inferred by browsing. **Guardar esta impresión** is optional; existing saved-card URLs remain available.

## Physical collection, missing cards and wishlist

This implementation is currently hidden from the app at the owner’s request and retained for a future redesign. The following documents its retained behavior.

Open **Mi colección** or **Lista de deseos** from Cartas or Ajustes. In the catalog dialog, choose the exact artwork and expand **Colección y deseos**. Browsing and opening these controls never imports the catalog or establishes physical ownership. Saving a wish or inventory lot privately caches only the selected printing when needed.

- Record your actual English copies, tradeable quantity, finish and storage location. Separate lots can represent different binders or finishes. Quantities are absolute totals, not incremental purchases. Reservations and tradeable copies cannot exceed owned copies; release reservations before reducing or deleting a reserved lot.
- From a deck, **Cartas que me faltan** opens the current version's physical requirements, including its leader and separate DON list. Alternate artworks and canonical reprints satisfy the same playing requirement. Tradeable copies and copies reserved by another deck are excluded. Unreserved availability is calculated for the selected deck; **Reservar copias disponibles** assigns those physical copies exclusively so another deck cannot count them again. The action can partially reserve an incomplete deck and adjusts surplus reservations to its current version.
- Editing a virtual deck keeps its physical reservations until you explicitly adjust or release them. Removing an unused deck releases its associated reservations without removing physical copies. **Liberar reservas del mazo** retains your inventory. Saving a virtual deck or recording a match does not declare ownership.
- A wish belongs to an exact artwork, with a total English-copy goal, priority and notes. Its progress counts all your owned English copies of that printing, including reserved/tradeable ones. Other artworks can complete a playable deck without completing an artwork-specific wish. Completed goals remain visible and editable; removing a wish keeps the physical collection.
- **Añadir faltantes … a deseos** targets the artwork represented in the list: currently owned copies of that exact printing plus the deck's missing copies. Repeating it preserves a higher existing goal, notes and priority. Detail links show the existing artwork-specific quotes/history when the provider supplies them; there are no purchase, price-alert or automatic acquisition actions.

Inventory/wish edits reject stale row timestamps rather than overwriting another tab, while stable submission IDs protect create retries. Database row locks and an atomic, expected-version reservation RPC prevent concurrent over-allocation. Private inventory, reservations and wishes are protected by RLS. The additive collection/wishlist migration is applied by `local:start` without resetting existing local data. Offline writes remain outside this deliverable.

## Security and data

All application tables have RLS. Private tables use owner checks; composite foreign keys enforce ownership of parent/version/event relationships. Shared cards and restrictions are read-only to authenticated clients. Owners can insert private, immutable manual cards; RLS and database triggers prevent cross-owner card references. `save_deck` and `save_deck_version` lock the owned parent and atomically save metadata, immutable snapshots, structured differences and import confirmation. An expected-version token rejects stale edits; metadata-only saves do not create redundant snapshots. The domain validator checks construction and dated restrictions, while complete tournament legality stays unverified without a reviewed restriction dataset. `save_match` saves the game and optional round in one transaction with a fixed submission ID. Event version/format must agree with all its games; archival preserves history and permits corrections of existing games.
